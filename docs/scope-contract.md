# Query scope contract

This page records which Lucid query paths apply the soft-delete scope, how each read mode behaves, and the tests that guard those boundaries. The mixin scopes model fetches; it is not a general database or authorization scope. See the [API reference](api.md) for lifecycle write semantics and the [tutorial](tutorial.md) for setup.

## Read modes

| Mode            | Predicate on the queried model                               |
| --------------- | ------------------------------------------------------------ |
| Default         | `deletedAt IS NULL`                                          |
| `withTrashed()` | No soft-delete predicate; active and trashed rows can match. |
| `onlyTrashed()` | `deletedAt IS NOT NULL`                                      |

Choose a mode independently for the root model and each relation query. Modes survive supported builder clones and pagination. For exact examples, see [read modes](api.md#read-modes) and [relationship aggregates](api.md#relationship-aggregates-and-existence-queries).

## Model fetches and builder lifecycle

| Query path or condition                                   | Contract                                                                                                                                                                                                                                                                        | Regression evidence                                                                                                                                                                                  |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `find*`, `first`, `exec`, `paginate`, `all`               | Default excludes trashed rows; `withTrashed()` and `onlyTrashed()` select the other modes.                                                                                                                                                                                      | [`scope.spec.ts`](../tests/unit/scope.spec.ts): OR grouping in default and only modes; [`model.spec.ts`](../tests/unit/model.spec.ts): ordinary queries hide trashed models.                         |
| `refresh()` on a trashed instance                         | Refreshes by identity with trashed rows included, so the instance receives its actual `deletedAt` value. A force-deleted instance cannot be refreshed because its row is gone.                                                                                                  | [`scope.spec.ts`](../tests/unit/scope.spec.ts): refreshes a trashed instance and rejects refresh after force delete.                                                                                 |
| Query clones, pagination count queries, preload callbacks | Preserve the selected mode, including the pagination count builder.                                                                                                                                                                                                             | [`scope.spec.ts`](../tests/unit/scope.spec.ts): mode survives clone and pagination count; [`scope_relations.spec.ts`](../tests/unit/scope_relations.spec.ts): preload/load callbacks.                |
| Reusing a builder across executions                       | Keeps caller predicates and replaces the previous scope filter rather than stacking it. Covers awaiting a builder twice, `paginate()` then `first()`, and builder `restore()` twice.                                                                                            | [`scope.spec.ts`](../tests/unit/scope.spec.ts): re-execution preserves caller predicates; [`builder_restore.spec.ts`](../tests/unit/builder_restore.spec.ts): repeated restore preserves predicates. |
| OR predicates                                             | Groups caller OR conditions before applying the default or only-trashed filter. `withTrashed()` adds no soft-delete predicate.                                                                                                                                                  | [`scope.spec.ts`](../tests/unit/scope.spec.ts): groups OR expressions in default and only modes; with mode survives clone.                                                                           |
| Aliased base tables and self-joins                        | Qualifies the predicate using the model's table alias or table name; a self-join does not treat the other alias as the fetched model.                                                                                                                                           | [`scope.spec.ts`](../tests/unit/scope.spec.ts): object and string aliases; qualified self-join.                                                                                                      |
| Subclass query hooks                                      | Appended OR predicates are regrouped before the installed filter. A hook that switches to `withTrashed()` after the mixin hook retains a filter already added; `clearWhere()` removes that filter along with caller predicates, and append-only protection does not restore it. | [`subclass_hooks.spec.ts`](../tests/unit/subclass_hooks.spec.ts): appended OR grouping, switching modes, and `clearWhere()` behavior.                                                                |
| Group-limited has-many and many-to-many preloads          | Filters related rows before applying each parent's per-group limit, so excluded rows do not consume the limit.                                                                                                                                                                  | [`group_limit.spec.ts`](../tests/unit/group_limit.spec.ts): has-many and many-to-many group limits in each mode.                                                                                     |

Builder lifecycle writes have their own rules and should not be inferred from read modes. See [builder lifecycle methods](api.md#builder-lifecycle-methods) and [destructive operations](../README.md#destructive-operations).

## Related model queries

| Query path                                                                                                    | Contract                                                                                                                                                                                         | Regression evidence                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `preload` and `load`: has-one, has-many, belongs-to, many-to-many, has-many-through, nested, self-referential | The fetched related model is scoped in its own default mode. Set a mode inside that relation's callback to include or select trashed related rows. The root mode does not switch relation modes. | [`scope_relations.spec.ts`](../tests/unit/scope_relations.spec.ts): has-one/has-many, belongs-to, many-to-many, has-many-through/nested, and self-referential relations. |
| `user.related('posts').query()`                                                                               | Applies the related model's default scope.                                                                                                                                                       | [`scope_relations.spec.ts`](../tests/unit/scope_relations.spec.ts): related queries exclude trashed related rows.                                                        |

Example with separate root and relation modes:

```ts
const users = await User.withTrashed().preload('posts', (posts) => posts.onlyTrashed())
```

Here the root includes all users while the preload includes only trashed posts. Each query is scoped independently.

### Relationship aggregates and existence queries

| Query path                                                                                  | Contract                                                                                                                                                                                                                                                                                                                                                 | Regression evidence                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `withCount`, `withAggregate`, `has`, `whereHas`, `doesntHave`, `loadCount`, `loadAggregate` | Applies the related model's scope inside the subquery. Put `withTrashed()` or `onlyTrashed()` in that relation callback to switch its mode; the parent's mode is unchanged.                                                                                                                                                                              | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): relation aggregate/existence default and callback modes; [`scope_aggregates.spec.ts`](../tests/unit/scope_aggregates.spec.ts): has-one, many-to-many, has-many-through, self-referential, and plain related models. |
| Relation aggregate `onQuery` callback                                                       | Still runs. Adding `whereNull('deleted_at')` repeats the default soft-delete predicate; it is usually unnecessary.                                                                                                                                                                                                                                       | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): `onQuery` callback scopes `withCount` to active children.                                                                                                                                                           |
| Self-referential aggregates and existence checks                                            | Qualify the related-model filter using Lucid's self-join alias.                                                                                                                                                                                                                                                                                          | [`scope_aggregates.spec.ts`](../tests/unit/scope_aggregates.spec.ts): self-referential aggregate and existence queries.                                                                                                                                                           |
| Has-many-through target and intermediate models                                             | Scopes the related target, not the intermediate table joined by Lucid. Thus an active comment may be returned through a soft-deleted post. A nested preload fetches posts separately and excludes that post and its nested comments. Add an explicit qualified predicate such as `whereNull('posts.deleted_at')` if the intermediate row must be active. | [`scope_relations.spec.ts`](../tests/unit/scope_relations.spec.ts): has-many-through and nested levels.                                                                                                                                                                           |
| Related model without `SoftDeletes`                                                         | The package leaves it alone; the presence of a coincidental `deletedAt` property does not install this scope.                                                                                                                                                                                                                                            | [`scope_aggregates.spec.ts`](../tests/unit/scope_aggregates.spec.ts): plain related model aggregate.                                                                                                                                                                              |

## Paths that bypass model fetch hooks

| Query path                     | Contract                                                                                                                                                                                                                                                  | Regression evidence                                                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `pojo()`                       | Bypasses model hydration and its fetch hooks; plain-object results can include active and trashed rows unless the query explicitly filters them.                                                                                                          | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): pojo `exec`, `first`, and `paginate` return both states.                   |
| Joins and embedded subqueries  | The scope applies to the query's model only. It does not add a predicate for a joined model or a model mentioned inside arbitrary SQL/subqueries. Qualify and add the needed predicate for each such table.                                               | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): a join from a model without soft deletes does not filter the joined users. |
| `db.from(...)` and raw queries | Bypass model fetch hooks; add an explicit predicate for the intended table and mapped timestamp column.                                                                                                                                                   | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): related query delete and `db.from` bypass the model scope.                 |
| Bulk `update` and `increment`  | Read modes do not scope these builder writes; matching trashed rows may also be updated/incremented.                                                                                                                                                      | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): bulk update and increment include trashed rows.                            |
| Builder `delete()` and `del()` | Physically delete matching rows, regardless of whether the builder is in default, `withTrashed()`, or `onlyTrashed()` read mode. Use `softDelete()` for bulk recoverable deletion or `forceDelete()` with an explicit trashed-only predicate for a purge. | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): builder `delete` and `del` physically remove rows in read modes.           |
| `related().query().delete()`   | Is a Lucid relation builder write, not an instance soft-delete call; the soft-delete read scope does not convert its physical delete.                                                                                                                     | [`scope_bypass.spec.ts`](../tests/unit/scope_bypass.spec.ts): related query delete physically removes rows.                              |

The query hook also does not provide authorization, tenant isolation, retention, or cascade behavior. Applications must supply those policies and predicates. A soft-deleted parent leaves child and pivot rows in place; a physical delete is governed by database foreign-key rules.
